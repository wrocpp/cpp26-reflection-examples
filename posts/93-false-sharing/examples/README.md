# False sharing: write contention benchmark

Companion to the wro.cpp post on false sharing. All numbers in the post come from the
CSV files here.

| File | What it is |
|---|---|
| `bench.cpp` | the benchmark: T threads each increment their own counter N times, 13 layouts |
| `run.sh` | `sh run.sh mac`, `sh run.sh docker`, `sh run.sh tls`: build, run, write results and env |
| `analyze.py` | markdown tables (median, min, max, CV, ratio to padded) from a results CSV |
| `results-mac-m2max.csv`, `results-docker-aarch64.csv` | raw rows, one per run (11 runs per cell) |
| `tables-*.md` | the post's tables, generated by `analyze.py` from the CSV |
| `env-*.txt` | machine, compiler, flags, load before and after, for each CSV |
| `layout_demo.cpp` | `static_assert`s on size, alignment and offsets plus a correctness-only run; the Compiler Explorer demo |
| `tls_addresses.cpp`, `tls-addresses.txt` | where `thread_local` counters of live threads sit |

Unit: wall nanoseconds per increment per thread (wall time from barrier release to the last
thread finishing, divided by the increments each thread did). Every run checks that the
counters sum to T times N.

## Notes on the kernels

- `atomic_kernel` and `plain_kernel` are `noinline` and take a reference, so every layout runs
  the same machine code. In a first version the plain loop on the packed array used a
  register-offset address and was about six times slower than the padded one at one thread.
- The plain kernel uses an `asm` memory operand and not `volatile`: GCC 16.2 on macOS folded a
  loop over a `volatile thread_local` into a single add.
- After the runs, one unneeded `#pragma GCC diagnostic` line was removed from `bench.cpp`
  (the file compiles without warnings under `-Wall -Wextra -Werror`). The GCC 16.2 assembly
  for macOS is identical before and after the edit.
